# Repository Guidelines

## Project Structure
- `src/` – TypeScript source for bot commands, events, utilities.
- `scripts/` – Node scripts for database setup and migrations.
- `dist/` – compiled output generated by the build; exclude from commits.
- Config files: `tsconfig.json`, `eslint.config.js`; add environment secrets in `.env`.

## Build, Test, and Development Commands
- `npm run dev` – run the bot with ts-node for local development.
- `npm run build` – compile TypeScript to `dist/`.
- `npm start` – execute compiled code.
- `npm run lint` – run ESLint with Prettier rules.
- `npm run db:setup` / `npm run db:migrate` – create or migrate PostgreSQL tables.

## Coding Style & Naming Conventions
- Use TypeScript with 2-space indentation.
- Modules and files in `camelCase`; classes in `PascalCase`; constants in `UPPER_SNAKE_CASE`.
- Prefer async/await; avoid `any` unless essential.
- Format code using ESLint/Prettier (`npm run lint`).

## Testing Guidelines
- No formal test suite yet. When adding features, include unit tests (Jest or Vitest) under `src/**/__tests__` and run them via `npm test`.
- Aim for meaningful coverage and clear test names.

## Commit & Pull Request Guidelines
- Use Conventional Commits (`feat:`, `fix:`, `docs:`).
- Limit commits to logical changes; keep PRs focused and linked to issues.
- Before submitting, run `npm run lint` and `npm run build`; include results or screenshots when relevant.
- Describe behaviour changes, database impacts, and manual test steps in the PR.

## Security & Configuration
- Store tokens and database credentials in `.env`; never commit this file.
- Rotate tokens if exposed and inform the team via secure channels.
